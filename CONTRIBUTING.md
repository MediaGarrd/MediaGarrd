# Contributing to MediaGarrd

## Submitting Issues
Open an issue [here](https://github.com/MediaGarrd/MediaGarrd/issues) and use the following to determine what labels to assign it:
- Repo Labels:
    - **THIS**: This label should be applied if the issue pertains to [MediaGarrd/MediaGarrd](https://github.com/MediaGarrd/MediaGarrd).
    - **SERVER**: This label should be applied if the issue pertains to [MediaGarrd/Server](https://github.com/MediaGarrd/Server).
    - **CLIENT**: This label should be applied if the issue pertains to [MediaGarrd/Client](https://github.com/MediaGarrd/Client).
    - **RECOVERY**: This label should be applied if the issue pertains to [MediaGarrd/Recovery](https://github.com/MediaGarrd/Recovery).
    - **OMARCHY**: This label should be applied if the issue pertains to [MediaGarrd/MediaGarrd-Omarchy](https://github.com/MediaGarrd/MediaGarrd-Omarchy).
- Issue-Type Labels
    - **feature**: This label should be applied if the issue is proposing a new feature or an enhancement to an existing feature.
    - **bug**: This label should be applied if the issue is identifying a bug or mistake in the codebase.
    - **documentation**: This label should be applied if the issue is related to updating/changing existing documentation.

Once this issue has been reviewed/approved, the **needs-triage** label will be removed and it will be transferred to the server repo where a PR can be opened referencing this issue.

## AI Usage

See [AGENTS.md](./AGENTS.md) for a more in-depth overview of the way AI is permitted in code submissions. If a signature is not present on a commit that even *appears* to be generated by an LLM, the PR will be closed. This is strictly for the continued maintainability of the project.
