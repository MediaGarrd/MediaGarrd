Scheduled backups for everything you self-host.

MediaGarrd zips the configuration of the services on your Docker host on a schedule, keeps the newest archives, and has a client on another machine pull every new archive off the host. Any service can be backed up: you give it a name and the host paths that matter.

How it works

1 Host paths /srv/radarr/config
/etc/nginx/sites-available
2 Server Mounts each service's paths read-only into a helper container and streams them into a zip.
3 Archive One archive per run. Only the newest are kept (10 by default).
4 Client Downloads the latest archive on its own schedule, on a different machine.
ServerRepo →

Runs next to the services it backs up and talks to Docker through /var/run/docker.sock.

  • Backs up every service on an interval (12 hours by default) and keeps the newest archives.
  • Never starts the helper containers. It only creates them, with the paths mounted read-only, and reads the files out through the Docker API.
  • Stores settings and services in a database on a mounted volume, so they survive rebuilds.
  • Is set up once from /config, unlocked with a PIN from its logs.
ClientRepo →

Runs anywhere else on your network. A backup on the same disk as the data doesn't protect much.

  • Finds servers with a quick LAN scan, by IP, or from MEDIAGARRD_SERVER_IP.
  • Downloads the latest archive on an interval (12 hours by default). These copies get an -AD suffix.
  • Starts a backup, downloads any archive, and shows the server's status.
  • Changes the server's settings and services after setup.
What it backs up

Anything you can point at. A service is just a name and a list of absolute host paths:

  • A directory includes everything inside it.
  • A file includes only that file.
  • Permissions, owners, modification times and symbolic links are kept.
  • If one path fails, none of it is included and the run is reported as partial, so you never get half a folder.

    Archives and restoring
    
    
    
      
    
        
    Archive Layout
    
        
    
          
    Each entry sits at its absolute host path without the leading /, with no folder per service. Services backing up /etc/nginx/sites-available/default and /srv/radarr/config produce:
    

    etc/nginx/sites-available/default
srv/radarr/config/
srv/radarr/config/config.xml
srv/radarr/config/radarr.db
srv/radarr/config/logs -> /var/log/radarr
    
          
    Hard links are stored as regular copies, and empty directories are kept. Named pipes, sockets and device files are skipped. If two services back up the same path, it appears once.
    
        
    
      
    
      
    
        
    Restoring
    
        
    
          
    The archive mirrors the filesystem, so restoring is a single extraction onto /. bsdtar (the libarchive-tools package on Debian/Ubuntu) restores contents, permissions, owners, modification times and symbolic links:
    
          
    sudo bsdtar -xpf 20261026-120000-000-media-backup.zip -C /
    
          
    To look inside a backup first, extract it into an empty directory with -C <dir>.
    
          
    
            unzip -o <archive>.zip -d / also works, but most distributions ship UnZip 6.00, which doesn't restore owners. Python's zipfile and most GUI archive managers restore only file contents.
          
    
        
    
      
    
    
    

    
    Install
    
    
    Both parts need Docker with Compose v2. The defaults in each compose file work as-is.
    
    
    
      
    
        
    1. Server, on the Docker hostREADME →
    
        
    
          
    git clone --depth 1 https://github.com/MediaGarrd/Server.git
cd Server
cp docker-compose.example.yml docker-compose.yml
docker compose up --build -d
    
          
    Get the setup PIN from the logs:
    
          
    docker logs mediagarrd-server 2>&1 | grep "Setup PIN"
    
          
    Then open http://<server-ip>:38471/config, enter the PIN, add your services and press Finish Setup.
    
        
    
      
    
      
    
        
    2. Client, on another machineREADME →
    
        
    
          
    git clone --depth 1 https://github.com/MediaGarrd/Client.git
cd Client
cp docker-compose.example.yml docker-compose.yml
docker compose up --build -d
    
          
    Open http://<client-ip>:8081 and connect to the server by IP. To connect without opening the page, add MEDIAGARRD_SERVER_IP=<server-ip> to the client's environment.
    
          
    A scan only sees servers on the client's own Docker network unless you add network_mode: host.
